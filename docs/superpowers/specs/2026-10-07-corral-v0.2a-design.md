# Corral v0.2a: cargar modelos, perfiles de GPU y verificación de claude-mem

**Fecha:** 2026-10-07
**Base:** spec `2026-10-06-corral-design.md` (v0.1 publicada). Este anexo adelanta parte de la v0.2 a pedido del usuario.

## 1. Cargar un modelo

- `OllamaClient::load(model, keep_alive)` hace `POST /api/generate` con `{"model": …, "keep_alive": …}` y sin prompt (precarga documentada por Ollama). Timeout de 120 s, porque cargar 6-17 GB tarda.
- Config nueva: `load_keep_alive: String`, por defecto `"30m"`. Valores ofrecidos en Ajustes: `"30m"`, `"1h"`, `"-1"` (siempre).
- Comando `load_model(name)`: usa el `keep_alive` de la config, despierta el poller y publica un aviso si falla.
- UI (Modelos): botón "Cargar" en cada fila instalada que no esté en la GPU y no sea alias interno. Muestra "Cargando…" y queda deshabilitado mientras carga.

## 2. Perfiles de GPU

En Ollama, la elección de GPUs es por servidor y se hace con variables de entorno. Corral la gestiona como un perfil.

**GPUs que ve Ollama.** Se leen de `%LOCALAPPDATA%\Ollama\server.log` (Linux: journal, fuera de alcance), tomando las líneas del último arranque:
- `msg="inference compute" id=0 filter_id=0 library=ROCm compute=gfx1101 name=ROCm0 description="AMD Radeon RX 7800 XT" … type=discrete total="16.0 GiB"`
- `msg="dropping integrated GPU; to enable, set OLLAMA_IGPU_ENABLE=1" id=1 library=Vulkan … description="AMD Radeon(TM) Graphics"`

`parse_ollama_gpus(log) -> Vec<OllamaGpu { id, filter_id, library, description, kind, total_mb, dropped }>` es una función pura. El "último arranque" son las líneas posteriores a la última aparición de `msg="inference compute"` precedida por un bloque de descubrimiento; en la práctica, se agrupan por la marca de tiempo más reciente del bloque de descubrimiento.

**Perfil** (config `gpu_profile`):
- `auto`: Ollama decide; borra las variables gestionadas.
- `spread`: `OLLAMA_SCHED_SPREAD=1`, que reparte siempre entre todas las GPUs visibles.
- `single { library, filter_id }`: solo esa GPU, con `HIP_VISIBLE_DEVICES` (ROCm en Windows), `ROCR_VISIBLE_DEVICES` (ROCm en Linux), `CUDA_VISIBLE_DEVICES` o `GGML_VK_VISIBLE_DEVICES` (Vulkan), con valor `filter_id`.
- Además, `igpu_enabled: bool` pone `OLLAMA_IGPU_ENABLE=1`.

`gpu_profile_env(profile, igpu_enabled, os) -> Vec<(nombre, Option<valor>)>` es pura y devuelve todas las variables gestionadas: `None` significa borrarla.

**Aplicar** (comando `apply_gpu_profile`):
1. Guarda la config.
2. Persiste las variables en el entorno de usuario de Windows (`HKCU\Environment` con `reg add`/`reg delete`), para que también las respete el autoarranque propio de Ollama.
3. Reinicia Ollama con `pause` + `resume`. El launcher aplica las mismas variables al proceso hijo (`env`/`env_remove`), porque el entorno de Corral es anterior al cambio.

claude-mem conserva su cola durante el reinicio (verificado en v0.1).

**UI (Ajustes → GPU):** lista de GPUs detectadas por Ollama (descripción, librería, tipo, VRAM, "ignorada" si la descartó). Opciones Automático / Repartir entre todas / Solo una GPU (selector), la casilla "Incluir GPU integrada" y el botón "Aplicar y reiniciar Ollama", con el texto "Ollama se reiniciará; claude-mem conserva su cola".

## 3. Verificación de claude-mem

El objetivo es detectar a tiempo lo que pasó el 2026-10-07: el modelo que usa claude-mem se borró y nada lo avisó.

**Fuentes:** `~/.claude-mem/settings.json` (`CLAUDE_MEM_PROVIDER`, `CLAUDE_MEM_OPENROUTER_BASE_URL`, `CLAUDE_MEM_OPENROUTER_MODEL`), `GET http://127.0.0.1:37777/api/health` (`ai.lastInteraction.{timestamp,success}`) y `GET /api/processing-status` (`queueDepth`). Timeout de 2 s.

**Verificaciones** (función pura `evaluate_claude_mem(inputs) -> Vec<Check { id, level: ok|warn|fail, message }>`):
1. `worker`: el worker responde. fail: "El worker de claude-mem no responde".
2. `endpoint`: el proveedor usa este Ollama (host:puerto de la base URL igual al de `ollama_url`). warn: "claude-mem no usa este Ollama: …".
3. `model_installed`: el modelo configurado existe en `/api/tags`. fail: "El modelo {m} no está instalado: claude-mem fallará cuando se descargue de memoria".
4. `model_loaded`: está en `/api/ps` (ok, o "no cargado: se cargará con la próxima observación").
5. `last_interaction`: la última interacción fue exitosa. fail si `success=false`; warn si tiene más de 1 h con cola mayor que cero.
6. `context`: `num_ctx` del modelo (parámetros de `/api/show`) ≥ 16384. warn si es menor: "claude-mem recicla su conversación cerca de 16k tokens; con menos contexto Ollama recorta el prompt".

Se expone como el comando `claude_mem_status() -> Option<ClaudeMemStatus>` (`None` si no hay claude-mem). La UI lo consulta cada 10 s mientras la pestaña Estado está visible.

**UI (Estado):** tarjeta "claude-mem" con proveedor, modelo, cola y la lista de verificaciones, cada una con ícono **y** texto (no solo color). Si alguna falla, el borde de la tarjeta usa el color de error.

## 4. Pruebas

Unitarias en Rust para `parse_ollama_gpus` (con líneas reales), `gpu_profile_env` (todas las combinaciones), `evaluate_claude_mem` (cada verificación en ok/warn/fail) y el parseo de `num_ctx`. Integración contra servidores falsos para `load` y para el estado de claude-mem. Vitest para los botones y la tarjeta. Un E2E por función.
